# 졸음 감지 (Drowsiness Detection)

## 1. 기능 개요

집중도 측정 중, 눈이 감기거나 게슴츠레하게 뜬 상태가 **약 15초 이상 연속**되면
졸음으로 판정하고 다음과 같이 알린다.

| 디바이스 벨소리 모드 | 알림 방식 |
| --- | --- |
| 소리 켜짐(normal) | 소리(미디어 볼륨, 이어폰 연결 시 이어폰) + 전체화면 팝업 |
| 진동(vibrate) | 진동 + 전체화면 팝업 |
| 무음(silent) | (어쩔 수 없이) 전체화면 팝업만 |

- 알림은 **눈을 다시 뜰 때까지** 지속되며, 눈을 뜨면 자동으로 닫힌다.
- 팝업의 "확인" 버튼으로 소리·진동만 먼저 끌 수 있다(팝업은 눈을 뜰 때까지 유지).

### 구현 위치
- `src/lib/useDrowsiness.ts` — 감지 로직(훅)
- `src/lib/alarm.ts` — 경고음/진동(공용)
- `src/lib/NativeBridge.ts` — `getRingerMode()` (벨소리 모드 조회)
- `src/pages/Study.tsx` — `DrowsinessAlert` 컴포넌트(팝업 + 알림 연동)
- `android/.../DeviceSoundPlugin.java` — 벨소리 모드 네이티브 플러그인

### 감지 방식
집중도 엔진(네이티브 Kotlin · 웹 MediaPipe)이 **공통으로** 1초 주기로 방출하는
`features.mean_ear`(최근 10초 평균 Eye Aspect Ratio)만 사용한다.

1. 세션 동안 `mean_ear` 샘플로 개인 "눈 뜬 상태" 베이스라인을 추정(90퍼센타일).
2. `mean_ear < 0.65 × baseline` 이면 눈 감김(게슴츠레 포함)으로 보고 지속시간 누적,
   `≥ 0.80 × baseline` 으로 회복하면 리셋(히스테리시스로 채터링 방지).
3. 누적 지속시간이 임계를 넘으면 경고.
   - **임계 시간은 설정에서 조절**한다(설정 → "졸음 감지 기준", 기본 15초, 3~120초).
     `settings.drowsinessThresholdSec` 로 저장되어 `useDrowsiness` 에 전달된다.
   - `mean_ear` 가 10초 트레일링 평균이라 눈 감은 뒤 임계 교차까지 ~3–4초 지연이 있어,
     내부적으로 설정값에서 `WINDOW_LAG_MS`(3.5초)를 차감한 값을 누적 임계로 사용해
     **설정한 초 ≈ 실제 연속 눈 감김 시간**이 되도록 보정한다.
   - 짧은 깜빡임(<0.5초)은 10초 평균에 거의 영향이 없어 오탐되지 않는다.

> 이 방식은 양 엔진이 이미 보내는 피처만 쓰므로 **파이프라인/네이티브 추론 코드 변경 없이**
> 웹·안드로이드에서 동일하게 동작한다. 추가된 네이티브 코드는 벨소리 모드 조회 1개뿐이다.

### 소리 출력(미디어 볼륨/이어폰)
경고음과 타이머 종료음 모두 **Web Audio(AudioContext)** 로 합성한다. 안드로이드 WebView에서
Web Audio 출력은 미디어 스트림(`STREAM_MUSIC`)으로 재생되므로:
- 이어폰이 연결돼 있으면 이어폰으로 라우팅되고,
- 벨소리/진동 모드와 무관하게 **미디어 볼륨**을 따른다.

졸음 경고는 정책상(소리/진동/무음) `getRingerMode()` 결과로 모달리티를 직접 게이팅한다.

## 2. 아키텍처 결정 — 졸음 단독 모드를 따로 만들 가치가 있는가?

### 결론: **별도 시스템(아키텍처)은 기각. 단, 같은 파이프라인의 "경량 플래그"로는 가치 있음.**

집중도 감지와 졸음 감지는 모두 **카메라 + MediaPipe FaceLandmarker(얼굴 랜드마크 추론)**
위에서 동작한다. 이 두 단계가 파이프라인 비용의 절대 다수를 차지하며, 졸음 감지(EAR)도
눈 랜드마크가 반드시 필요하므로 **공유·필수**다. 따라서 졸음만을 위한 별도 카메라/추론
스택을 새로 만드는 것은 의미가 없다 → **별도 아키텍처 기각.**

다만 집중도에만 들어가는 단계는 졸음 감지에 **불필요**하다:

| 단계 | 집중도 | 졸음만 | 비용 |
| --- | :---: | :---: | --- |
| 카메라 캡처 | ● | ● | (공유, 큼) |
| FaceLandmarker 추론 | ● | ● | (공유, 가장 큼) |
| GazeTracker (시선/EAR) | ● | ● (EAR만) | 작음 |
| **rPPG ROI 샘플링 + HRV(FFT)** | ● | ✕ | 중간 |
| **ML 분류기(ONNX/로컬) 추론** | ● | ✕ | 중간 |
| FeatureExtractor 전체 | ● | 일부 | 작음 |

즉 졸음 단독 모드는 **rPPG/HRV + ONNX 추론**을 건너뛸 수 있어, 분석 스레드 CPU와
배터리에서 **유의미한(대략 20~35% 추정) 절감**이 가능하다. "딱히 차이가 없으면 기각"의
조건에 해당하지 않는다 — 차이는 존재한다.

### 결정 → 구현 (라이트 모드)
권장대로 **새 아키텍처가 아니라 기존 파이프라인의 경량 플래그(`lightMode`)** 로 구현했다.

- **웹**: `FocusPipeline.init(lightMode)` 에서 ONNX/로컬 모델 로드를 생략하고,
  `processFrame` 에서 **rPPG(ROI 샘플링 + HRV) 와 ML 분류기 추론을 스킵**한다.
  FaceLandmarker→GazeTracker(EAR)와 FeatureExtractor(mean_ear)는 유지하므로 졸음 감지는 그대로 동작.
- **네이티브**: `FocusPipeline.kt` / `FocusPlugin.startPipeline({ lightMode })` 동일하게 분기.
- **UI**: 집중도 패널에 모드 선택 토글 **[집중도 + 졸음] | [졸음만(라이트)]** 추가.
  - 라이트 모드로 시작하면 집중 점수/생체신호 탭 대신 `LightModeStatus`(눈 상태 감시) 카드를 보여주고,
    NaN 점수는 집중도 이력/개인화 평점에서 제외한다.
- 집중도 측정 중에는 졸음 감지가 **항상 함께** 동작한다(추가 비용 ≈ 0 — 이미 흐르는 EAR 피처 사용).

관련 파일: `src/lib/focus/pipeline.ts`, `src/lib/useFocusWeb.ts`, `src/lib/useFocusNative.ts`,
`src/pages/Study.tsx`, `android/.../FocusPipeline.kt`, `android/.../FocusPlugin.kt`.

## 3. 테스트 타이머 종료음 (확인 결과)

**기존 동작**: 테스트 타이머가 끝나면 `showNotification` 팝업만 떴고 **소리는 전혀 나지
않았다**(무음).

**변경**: 종료 시 `playTimerEndSound()` 로 미디어 볼륨 상승 3음 차임을 재생한다.
- Web Audio → `STREAM_MUSIC`(미디어 볼륨)로 출력되므로, 기기가 진동 모드라도 **이어폰이
  연결돼 있으면 이어폰으로** 종료음이 나간다.
- 벨소리/진동/무음 모드와 무관하게 미디어 볼륨을 따른다(요구사항과 일치).
